## 二、 赛题五项核心能力逐项对齐规格

赛题要求防护一个真实在线运行、具备调用工具、读写文件、访问网络、操作 MCP、派发子 Agent 能力的 LLM Agent。系统形态采用**工具侧 Hook + API 侧网关 + 共享防护内核**。**双镜 D²Guard** 的技术实现对齐如下：

### 能力 1：多源注入识别 (Multi-Source Injection Detection)
* **要求覆盖的三类来源**：
  1. **直接注入**：识别来自用户输入的越权指令、角色伪装、上下文劫持；
  2. **间接注入**：识别来自 URL 网页内容、文档解析结果、源码文本、工单/邮件/Issue、MCP 工具返回字段、工具注册描述信息；
  3. **记忆污染**：识别跨会话长期记忆库、向量数据库、业务知识库中预先植入的隐性触发指令与污染内容。
* **D²Guard 落地实现**：
  * **网关与 Hook 双向感知**：网关截获模型通信中的 Prompt 增量，Hook 截获工具返回与记忆读写增量，封装为标准 `D2Event`；
  * **【快镜】本地毫秒级初筛**：快镜（Laya 400M）对增量文本进行非自回归定型分类，快速识别指令诱导与注入特征；
  * **记忆召回独立审查**：长期记忆在召回注入 Agent 上下文前，单独作为增量事件提交快镜初筛，阻断休眠指令激活。

### 能力 2：意图—计划—工具语义对齐 (Intent-Plan-Tool Semantic Alignment)
* **官方要求**：
  * 精准刻画“用户原始任务意图”与“Agent 实际执行计划/动作”之间的语义偏离度；
  * 输出清晰、可落地的研判结论（官方范例：*“用户原始请求为读取项目 README 文档，Agent 却调用 fs.read 读取本地 SSH 私钥文件，并通过 net.fetch 向外部未知域名发起数据传输，判定为间接提示注入引发的工具滥用行为”*）。
* **D²Guard 落地实现**：
  * **安全状态聚合机**：在内存中锁定用户初始任务授权锚点，记录已读敏感数据登记薄（Secret Ledger）；
  * **【慢镜】深度裁判输出中文判词**：唤醒慢镜（DeepSeek 大模型），仅对当前的精选增量证据包做深度思考，输出标准的结构化裁判报告，清晰解释偏离原因。

### 能力 3：细粒度工具策略与三态决策 (Fine-Grained Policy & Tri-State Gating)
* **官方强制要求的 5 条精细化管控规则**：
  1. `fs.write`：严禁向 `~/.ssh/`、`~/.aws/`、`/etc/cron.*`、系统自启动目录等敏感路径写入文件；
  2. `net.fetch`：严禁将当前会话内读取的本地敏感文件、密钥信息外发至非信任域名；
  3. `exec`：严禁执行 Base64 解码后执行（`base64 -d | sh`）、远程下载管道执行（`curl | bash`）等等价恶意命令；
  4. `git.push`：用户原始任务为代码检视时，严禁触发代码提交与推送操作；
  5. **子 Agent 派发**：严禁向后台子 Agent 传递当前会话内的密钥、凭证等敏感信息。
* **官方决策要求**：支持运行时风险评估，触发**“合规放行 (Allow)、询问用户确认 (Ask)、强制阻断操作 (Block)”**三种决策。
* **D²Guard 落地实现**：
  * 内核策略引擎评估声明式 YAML 策略 DSL 与 Shell AST 语法分析，向 Hook 与网关回传控制参数：`{"verdict": "ALLOW" | "ASK" | "BLOCK", "reason": "..."}`；
  * Hook 插件在底层工具真正执行前实施物理阻断，明确禁止项直接拒绝执行。

### 能力 4：跨 MCP 与子 Agent 溯源 (Cross-MCP & Sub-Agent Provenance)
* **官方全链路还原要求**：
  1. 明确攻击触发源：用户输入、外部读取资源、记忆库污染内容；
  2. 梳理全链路节点：经过的主 Agent、子 Agent、中转 MCP 代理节点；
  3. 定位上下文来源：标记攻击载荷对应的 **Token 级文本来源与归属**；
  4. 记录调用详情：全量工具调用记录、传入参数、返回结果；
  5. 明确影响范围：被操作的本地文件、外发网络目标、操作的 Git 仓库、访问的凭据库；
  6. **最终输出可视化的攻击路径有向无环图（DAG）与时序链路图**。
* **D²Guard 落地实现**：
  * **增量事件流即天然拓扑**：增量 JSON 数据流天然带有先后时序与因果关联（带 `parent_id`）；
  * **一键导出交互式 HTML DAG**：内核内置 Mermaid 渲染器，直观展示输入源、传播节点、阻断断点与受影响资产，支持 Token 级切片高亮显示。

### 能力 5：对抗鲁棒性 (Anti-Bypass Robustness)
* **官方要求覆盖的 7 类绕过手法**：
  1. 多语言混淆绕过：中、英、日、俄多语言与 Emoji 混排；
  2. Unicode 变形绕过：西里尔与拉丁同形替换、零宽字符、不可见字符；
  3. 分词指令拆分绕过：恶意命令分片拼接、多轮对话拆分注入、空白间隔变形；
  4. 分隔符注释绕过：`/* */`、`#` 注释内嵌截断，`;`、`&&` 拼接；
  5. 字符格式绕过：大小写混排、全半角符号替换、特殊编码伪装；
  6. 上下文稀释绕过：超长对话内容稀释前置安全规则，诱导遗忘约束；
  7. 语义伪装绕过：将恶意指令包装为正常系统维护或诊断业务。
* **D²Guard 落地实现**：
  * 前置清洗器处理多语言、Unicode、注释与编码（1~5 类）；
  * 安全状态聚合机独立持久化初始授权，天然免疫长上下文稀释（第 6 类）；慢镜精选证据包比对识破业务伪装（第 7 类）。

## 三、 官方评审重点与加分策略

根据安天官方评价方式：**“功能完成度 + 技术先进性 + 工程化质量 + 攻防对抗验证”**，加分项布局如下：

1. **行业已知真实间接注入漏洞防御复现（官方明确加分项）**：
   * 构造对齐类似 Copilot / MCP 真实利用链的完整攻防场景；
   * 在实测中完整演示：**无防护下漏洞利用得手 $\to$ 开启 D²Guard 后在执行前精准阻断 $\to$ 导出复盘 DAG 图**。
2. **企业级业务落地可行性（官方明确加分项）**：
   * 架构解耦：Hook 守工具底层，网关守模型进出，内核集中运算，可平滑嵌入现有企业 Agent 体系；
   * 快镜本地推断延迟 **< 20ms**，相较于纯大模型审查（>1500ms）性能提升近百倍，业务无感。
