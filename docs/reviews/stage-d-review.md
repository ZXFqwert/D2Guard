## S1 训练：问题与原因

**表现。** 在 C/C2 金标准片段上，微调版全面不如原版：

| 模型 | C 金标准 to_agent 命中 | C2 金标准 to_agent 命中 | C2 data 误判 |
|---|---|---|---|
| 原版英文 | 1/28 | 10/43 | 227/564 |
| 原版多语言 | 0/28 | 0/43 | 25/564 |
| D²Guard-Laya（本阶段） | **0/28** | **4/43** | **236/564** |
| Gemma4 裁判 | 21/28 | 22/43（另有 14 条判为 quoted） | 5/564 |

即便是作为上限参照的 Gemma4 裁判，在 C2 上也只检出约一半 to_agent。分歧集中在 to_agent 与 quoted 之间，说明裁判与金标准对“引用”的定义并不一致。D′ 中的裁判复核必须使用与金标准相同的定义（`docs/stage-c2-gold/RUBRIC.md` 第二部分）。

**原因（按影响大小排序）：**

1. **训练数据太少。** 只有 136 条训练文本（680 个问题项），4 个 epoch，用时 90 秒。训练 loss 依次为 0.354 → 0.097 → 0.006 → 0.0005，几乎是背下了训练集；验证准确率只有 65%，温度拟合触到 5.0 的上限。这是典型的过拟合。
2. **领域完全不对。** 81% 的数据是自写的“博物馆、浮标、果园”集合，其余是 Flask、CPython、Click 的官方文档；唯一的公开注入数据 BIPIA 15 条全部被隔离。模型从没见过“软件仓库里写给 Agent 的指令”，自然无法迁移。根源在于把“排除评测模板家族”执行成了“排除整个任务领域”。D5 的原文“排除它们及其模板家族”表述不清，这是评审方的责任；准确含义已写入设计文档 §9：排除原文、近似重复和载荷句式，不排除领域。
3. **类别先验不对。** 训练集四类等量（各约 25%），评测中 data 占 92%。模型因此大量把普通数据判成 for_reader。
4. **主指标没有对准用途。** 四类 macro-F1 把样本中不存在的类别计为 0，C 金标准上最高只能到 0.5，数值波动大，掩盖了“to_agent 一个都没检出”这个关键事实。运行时真正用到的是 to_agent 的二分类判断。
5. **人工式逐条裁定拖慢了流程，也限制了规模。** 455 个候选经过双教师标注，再由 Codex 逐条裁定，结果只保留 404 条。阶段 D′ 改为“生成契约 + Gemma4 复核，两者一致才入库”，以换取规模。

**安全问题（必须先修）：** `core.py` 第 227 行，S1 只要高置信判为“非 to_agent”，就会清空规则得到的 unknowns。按这个模型的表现，它会把真实注入高置信地判为 data，从而取消 DT-5 兜底。阶段 D 的 A/B 四格之所以没有暴露这个问题，是因为攻击轮由 DT-4a 拦下，没有走到 DT-5。已在设计文档 §9 增加“S1 只能增加风险”，并在 D′0a 要求修改，修好前 S1 默认不启用。

**做得对的部分：** 先核实接口再实现，没有猜；原版权重全部未被覆盖；温度与阈值只在验证集上拟合；没有用评测集调参或挑选模型；如实报告了退化结果。
