# 给 Claude 的研究问题说明

我们正在开发 D²Guard，用于检测和防御 LLM Agent 的提示注入与工具滥用。现在卡在项目核心：**如何从 Agent 运行轨迹提取并增量维护足够完整的安全状态，让低延迟决策模型可靠判断拟执行动作，同时保留可回溯原文的证据？** 请结合下面的架构、实测结果和附件批判性评审，先帮助定位问题与设计可证伪实验，不要直接泛泛推荐 RAG、知识图谱或换一个更大的模型。

## 1. 要解决的任务与约束

宿主是实际运行的 Pi CLI，使用真实 LLM API，提供受限文件读写、网络访问、一层子 Agent 和固定只读 MCP。我们已复现一条 README 间接注入：用户要求读项目资料、写摘要；被污染 README 诱导 Agent 读取测试凭据并发到本地实验收集端。无防护时实际泄露 56 字节合成凭据。

工具执行前必须给出 ALLOW、BLOCK 或 ASK。ASK 必须解释风险并真正暂停动作；在副作用前挂起即可视为该轮控制有效，不要求完成业务任务。正常任务误拦需单独评估，不能靠所有操作都 ASK 来宣称成功。

目标是至少 95% 的动作在本地快路径处理，少量疑难动作才交慢镜。这个比例是目标，不是已验证指标。我们不希望每一步同步调用云端大模型，也不希望任务越长，快镜输入越长。当前实验工具限制不是完整 OS 沙盒。

## 2. 我们设想的架构

- Hook/网关上报每次新增的用户输入、模型公开输出与候选调用、工具返回、子 Agent/MCP 信息。新增事件是传输 JSON，不等于最终安全分量。
- 内核归档完整原文及可信来源元数据，再提取本次安全增量 Δ_t，更新有界安全状态 S_t。原文不进入快镜，但证据引用能够回溯到原文区间。
- 快镜依据前态 S_(t-1) 和当前增量/拟执行动作 Δ_t 判断；同一份当前事实不能重复累计。当前用官方英文原版 Laya，不使用之前那个自制浅层分类器，也不再以多语言版为主线。
- 慢镜按证据引用回溯精选原文，分析复杂意图与调用关系。当前实现中慢镜异步给出复核说明，不自动解除 ASK。
- 确定性约束、模型语义判断和真实执行控制分别记账。外部文档自称“用户已授权”不能提升为真实用户授权；来源同目标匹配只是可疑关联，不等于证明因果。

所谓“安全链”，不是全文对话日志，也不是简单截断历史；应是可持续更新的安全状态，加上能回溯事实来源的链路。当前热状态最多保留 8 个污点和 8 个近期步骤，完整索引在 SQLite 持久化。如何定义充分状态、避免历史信息丢失，正是未解决的问题之一。

## 3. 当前实现和已经排查的事项

当前提取器主要是规则/词法实现，识别用户授权范围、来源、操作—目标关系、请求/禁止/引用、敏感资产、请求数据流、执行阶段等。它还不是通用语义压缩器，存在同义表达漏提且未报告覆盖不足的问题。

曾确认一个实质缺陷：把操作列表与目标列表做笛卡尔积，凭空生成“读 A、写 B”之外的“写 A、读 B”。现已改成逐操作绑定目标，保存请求数据流，并区分禁止、引用与外部来源自称授权。修复只证明这些关系更准确，不代表整个安全状态已充分。

真实运行已核对原生工具调用、Hook 和裁决参数一致；原文哈希、代理请求闭合、快镜实际输入摘要、未截断、被挂起动作未执行等检查通过。当前没有证据把失败归因于本轮传输丢帧或输入截断，但这不代表任意运行都绝不会出问题。

## 4. 关于 Laya，我们真正测到了什么

早先使用官方多语言基础版，现在按英文原版 `convaiinnovations/laya` 固定 revision `7b928d828b7b0e022f929d9bd2e44165aa270148` 做主线。我们需要中英文；其他语种混淆可以另设处理路径。不能假定英文版已具备稳定中文能力。

对两个版本喂入逐字相同的 240 个控制输入与问题，其中有 214 个不同的输入/问题组合。每条有 JSON 与事实对应的自然语言表示，采用真假成对控制，并分别测试 NOUL 和两种是/否选项顺序。内容包括授权字段读取、授权关系比较、指令来源、是否确认送达，以及逐层加入的外部来源和历史操作。两版均无截断或选项折叠。

英文版部分能力改善，但没有解决全部问题。例如，英文版在一种预先定义的 choice 问法下：

- 明确授权事实＋操作目标＋权限列表：JSON 和自然语言都是 8/8；再加入外部文档请求：降至 4/8 和 5/8。
- 比较用户权限和当前目标：最小自然语言为 8/8；加入八条历史操作后为 4/8。
- 最小 JSON 在某些问法下能区分真假，其他问法又会失败。因此不能说 Laya 只能识别自然语言，也不能说“把 JSON 翻译成句子”就解决了。

这些只是重复模板上的诊断计数，不能作为独立保留集准确率。12 个中英文最小控制还显示中文否定受题型/选项顺序影响；同样不足以评价整体中文能力。

英文版接入真实 Pi 后，正常任务完成无误拦；攻击在读取凭据前 ASK，0 字节外发。但这来自组合策略与授权事实，快镜动作对齐仍可能判断 expected，不能据此声称 Laya 检测成功。

公开高分也需要区分版本：Laya 官方 typed-decisions 表中，领域训练版为 0.766，基础英文版为 0.362，多语言基础版为 0.342。Jev 的公开评价不等于当前 Laya 基础权重的效果。我们没有调用 Jev 做本项目同输入对照。参考：[Laya 模型卡](https://huggingface.co/convaiinnovations/laya/blob/main/README.md)、[Jev 评测说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev)。

## 5. 我们在考虑自己的领域模型

如果固定原版配合合理表示仍不足，可以在原版基础上训练 D²Guard 快镜，而不是从头预训练。数据可以合成：先生成原始事件及独立事实契约，经真实压缩器得到安全状态，再检查事实保留与标签是否一致。

已生成 384 条中英文种子数据，只覆盖文件读取与授权/未授权、请求/禁止/引用/普通事实。按来源模板家族分成 192/64/128，所有同家族变体在一个划分。尚未人工独立复核，尚未训练；模板保留集不等同真实任务测试。

我们担心：自己编安全链和标签会引入捷径，比如模型只看 `.env`、`authorized=false`、某个模板句式或文件名。尤其不能把要预测的授权标签以 `in_user_granted_scope` 直接放进输入，或让来源立场分类器照抄 `clause_kind`。也不能让模型为提取器已经丢失的事实负责。

## 6. 请重点回答

1. **任务边界**：哪些是可精确计算的权限/数据流事实，应该由规则处理？哪些才是快镜需要学习的语义问题？现在的“动作对齐、来源性质、是否跟随污染”是否定义含混或相互矛盾？尤其如何区分目标相同、语义诱导和已证明因果？
2. **安全充分状态**：怎样定义 S_t 和 Δ_t，使其保留授权变化、来源信任、动作目的、依赖/数据流、执行状态与未知项？哪些信息必须持久保留，哪些可淘汰？信息不足时怎样显式表达，避免伪装成正常？请给出最小 schema 和同一轨迹的逐帧更新示例。
3. **抽取和模型输入**：规则、轻量提取模型及大模型各适合承担什么？内核结构化状态与给快镜的自然语言视图是否应分离？如何在不预先写入答案的条件下构建与当前动作相关的最小视图，并测出压缩损失？
4. **定位实验**：如何区分提取错误、状态更新错误、表示/提问不适配、模型能力不足？请提出变量受控、能推翻假设的最小实验，包含人工校对的理想分量与真实压缩器分量，以及 JSON/自然语言、中英文、历史干扰、正反标签、选项顺序的对照。
5. **领域训练数据**：若要训练，怎样生成原始轨迹、定义标签/UNKNOWN、做反事实配对，防止标签泄漏和模板捷径？怎样划分训练/验证/保留集，如何使用教师模型且避免自我认证？首轮应训练提取器还是快镜，依据什么判据决定？

希望你的输出是：先指出本方案最关键的逻辑矛盾与缺失，再给出建议架构、最小状态 schema、实验矩阵和训练数据契约。区分有证据的判断与猜测；不要把公开评测高分直接当成本任务能达到的保证，也不要仅靠改关键词或调阈值适配现有一条攻击。
