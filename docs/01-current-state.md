# 项目现状与迁移边界

2026 年 10 月 16 日核查后决定采用独立新主线，旧版本冻结为参考。新版本先完成 Pi CLI 真实攻防，再扩展 D2Guard 能力，最后实现 Web 与 Electron 展示。

## 新主线最新状态（2026-10-16）

`d2guard-next` 默认使用 `d2v2`，前轮部署基线提交 `6644977`。已接通 Pi 增量 Hook、SQLite 原文与安全状态索引、官方原版 Laya、按引用回溯的异步慢镜、流式 API 代理和固定只读服务的真实 stdio MCP。旧 `m1`、`d2core` 保留复现。

同一 README 注入在无防护时实际外发 56 字节合成凭据；开启新内核后，在 `.env` 读取执行前 ASK，接收端 0 字节。正常任务开启防护的独立复测完成，无误拦。该结果只证明当前样本的执行前控制与证据闭环，不能推导总体防御率或 D1 的独立必要性。

当前阶段二尚未全部验收：A100 上真实 Pi 四组对照已通过，快镜中位数约 30–35ms，完整裁决约 34–39ms，CPU 秒级计算瓶颈已通过迁移改善。但原版 Laya 的跟随分数在正常/异常输入均偏高，语义区分能力仍需研究。一次旧 Windows Pi 原生退出原因未定，另一次旧子 Agent 超时后重派成功，算力机首次 stdin 启动中断也保留。详见 [算力机验证](07-compute-validation.md)。扩库和前端继续暂停。

当前 46 项 Python 测试在两台机器通过，Windows 3 项 Node 测试通过；测试用模型替身验证协议不变量，真实模型效果另以原始运行证据验真，两者不能混算。

本轮进一步修复安全压缩器的操作—目标笛卡尔积错误、POST 误关联 GET、否定作用域及并列宾语丢失，并保存来源到目标的数据流请求。新一轮真实四组对照及最终两轮防护复测均通过；单样本防护成功仍不能证明 D1 语义识别成功。36 组表示/问题控制和 11 组后续控制显示：最小 JSON 能区分，复杂状态的授权字段翻转仍不可靠。详见 [安全语义诊断与修复](08-security-semantics.md)。

## 旧版现状

旧版 207 项 pytest 通过，TypeScript 与 Vite 构建通过。但独立进程探针发现：没有模型时 PB01 的 live 路径仍在 3.73 秒内外发 25 字节；pytest 标志改变同一路径；安全完成的模型环结果也被追加回放覆盖。开启防护可阻断这条预设外发。因此旧内核有工作基础，旧 live 统计不代表真实模型攻防。

最新源码修改于 10 月 16 日上午，原 Windows 包生成于 10 月 15 日晚。公网入口核查时连接关闭，线上版本未确认。旧工作区无 Git 元数据，历史提交对应关系未确认。

## 当前可用环境

- Windows 本机 Node 24.15.0，Pi 0.85.1 已安装。
- 沿用旧版用户配置的模型接口，认证信息仅从本地配置读取；模型列表接口已连通。
- Windows 当前无已确认可用的 Docker 或 WSL Linux 发行版。算力机已通过 Mesh SSH 接入；先前公钥认证失败是未解锁私钥，不能继续视为网络/权限不可用。A100 独立环境与具体限制见 [算力机验证](07-compute-validation.md)。
- 首轮使用限制文件范围和网络目标的实验工具，禁止任意 Shell。完整命令执行及 OS 级隔离属于后续独立验收项。

旧源码参考 ZIP 与逐文件清单位于 `../../archive/2026-10-16-legacy/`，原文件、发行包和运行数据保留原位。新版本不导入旧 Agent 运行器、回放控制器或成功率数据。归一化、账本、审批与策略仅为候选复用组件。
