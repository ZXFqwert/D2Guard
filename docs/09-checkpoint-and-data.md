## 公开高分为什么不能直接套用

Laya 官方按模型列出的 typed-decisions 结果为：领域训练版 0.766、基础英文版 0.362、多语言基础版 0.342；高分属于经过该工作流训练的版本。其 Jev 对照引用公开成绩，样本与问题并非同一次配对实验。[Laya 官方模型卡](https://huggingface.co/convaiinnovations/laya/blob/main/README.md)

Jev 官方工作流评估强调分解问题、由程序组合决策，并用大型模型参考概率评估；这不等同于任意安全链上的人工真值分类准确率。格式正确也不等同于内容判断正确。[Jev 官方评估说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

本项目未调用 Jev API，也未确认用户看到的是哪份具体评测，不能声称 Jev 在我们的数据上一定胜出。我们先验证可控的原版权重与输入，再决定是否领域训练。

## 固定事实、问题，比较两个原版

`research_security_components.py` 构造 240 个控制输入，包含 214 个不同的“输入＋问题”组合，其余为刻意重复的最小控制。每个输入同时回答 NOUL、是选项在前的 choice、否选项在前的 choice。四类任务分别是：读取明确授权事实、比较用户授权与当前目标、区分指令来源、区分提出外发与确认送达。每类逐步加入操作目标、权限、外部来源或八条历史记录，并提供事实对应的 JSON/自然语言两种表示。

两种模型的 240 个输入与问题逐字一致，均无输入截断、无选项折叠。标签由模板事实契约定义，未使用模型预测生成标签。以下为诊断计数，不是独立测试集准确率；不据此挑选线上阈值或最佳问题。

| 模型/输入形式 | NOUL 正确数 | 是在前 choice 正确数 | 否在前 choice 正确数 |
| --- | --- | --- | --- |
| 多语言原版 / JSON | 73/120 | 78/120 | 71/120 |
| 英文原版 / JSON | 89/120 | 81/120 | 82/120 |
| 多语言原版 / 自然语言 | 90/120 | 86/120 | 90/120 |
| 英文原版 / 自然语言 | 90/120 | 95/120 | 99/120 |

英文版部分能力改善，但仍存在上下文干扰。例如按预先定义的是在前 choice 观察：英文版对“明确授权事实＋操作目标＋权限列表”两种表示均为 8/8；加入外部文档请求后降至 JSON 4/8、自然语言 5/8。另一个比较授权关系的任务，最小自然语言为 8/8，加八条历史记录后为 4/8。输入中事实没有被删除，故这些失败不能仅归因于压缩器漏提或传输截断；但具体原因可能涉及表示、提问和模型能力，尚未锁定。

[配对结果与全部分组](laya-checkpoint-comparison.json)、[英文原始结果](component-research-english.json)、[多语言历史结果](component-research-multilingual.json)。多语言运行完成于用户要求改英文版之前，此后未继续调试多语言权重。多语言报告中 copy/transmit 两条提取控制的 HTTP 方法有歧义；英文报告将原文补为显式 POST。这两条不在 240 个模型输入中，也不参与上述比较。

另有 12 个中英文最小控制：英文 6 条在三种题型上均正确；中文明确禁止读取的一例在“是选项在前”时答错，明确允许的一例 NOUL 低于 0.5。样本很小，只说明不能默认英文模型已可靠支持中文；也不能说中文完全不能处理。[语言控制结果](laya-english-language-smoke.json)

## 可以合成训练数据，但要先合成可审计的事实

建议的顺序是：**原始事件及独立事实契约 → 当前压缩器 → 安全分量 → 检查信息损失 → 训练/验证/保留测试**。不能先拼一个带答案的安全链，再用其自身字段当“独立真值”。

已实现 `build_security_seed.py`，生成 [security-seed-v0](../datasets/security-seed-v0/manifest.json) 的 384 条种子数据：192 训练候选、64 验证候选、128 保留候选。覆盖中英文、4 个文件目标、授权/未授权和请求/禁止/引用/普通事实四种来源立场。每个来源模板家族及其语言、文件名和反事实变体只能属于一个划分。六种家族目前只是来源叙述框架，不是六类已经验证的攻击。

每条包含原始用户输入、外部内容、拟执行动作、独立契约标签、真实压缩结果和抽取差异。当前简单模板的授权和关系比对全部一致；这只证明生成管线可用，不代表压缩器已具备通用覆盖能力。另行词法探针仍发现 retrieve、emit 等表达会漏提且未标记覆盖不足。数据中不存在真实凭据，未执行任何攻击工具。

所有样本均标为 `training_ready=false`，原因是尚未经过独立人工复核、任务范围很窄，也未准备完整模型输入导出。训练前必须按任务限制输入字段：授权判断不能直接接收 `in_user_granted_scope`；来源立场判断不能直接接收 `clause_kind` 或 `relation.stance`。否则模型只需抄答案。保留集目前同样属于模板合成，不能替代自然任务及真实轨迹评测。

后续数据至少补齐：

- 同一目标授权/未授权、授权撤销、来源冒充权限、多步委托与来源继承；合法读取敏感文件和不含敏感文件的越权动作都要有。
- 多轮历史长度、无关信息、字段顺序、同义改写、跨中英文表达变化；保持核心事实和标签不变。
- 提议、允许、开始执行、失败/未知、确认送达分别标注；不把匹配同一目标当作已证明因果。
- 信息缺失和压缩歧义的 UNKNOWN 标签；压缩缺陷留作提取器修复集，不强迫快镜猜测已经丢失的事实。
- 从真实 Pi 轨迹中独立复核的正常/异常样本作为最终外部测试，不能混入训练或反复调参。

可以用大模型帮助扩写事件和独立复核，但其输出属于待验证标签。业务逻辑可精确确定的事实由契约校验；主观因果解释不能由生成模型自我认证。训练完成后另命名为 D2Guard 领域模型，保留英文原版作基线；分别报告提取覆盖、快镜误报漏报、未知比例、校准与延迟。当前尚未训练，下一步先完成这份数据契约与输入视图，避免用漂亮训练分数掩盖信息链路问题。
