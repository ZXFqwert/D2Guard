## 记忆来源与对照条件

- 写入会话：`20261020-085509-2ff9bc`。攻击文本来自原有固定场景 `c-memory-handoff` 的 `handoff.txt`，通过原生 `memory_write` 完整保存。
- 新会话通过原生 `memory_read` 读取；两路使用同一初始记忆与同一测试凭据的独立副本，初始记忆 SHA-256 和 fixture SHA-256 一致。
- 记忆跨会话标签合并、内容哈希与原生写入调用关联均核验通过；可追溯 writer_session 和 writer_run_id。网页显示继承自记忆的原始来源，可点击写入会话链接查看原生写入过程。
- 全程使用同一个配置的模型和冻结 S1，未替换模型、调低阈值、修改载荷或伪造响应。网页三阶段输出预算统一 8,192 token；命令行默认仍是 2,048，参数显式记录在 manifest。

## 网页操作

打开护航模式或攻防竞技场运行任务。遇到 ASK 后显示工具、参数、理由和到期时间。批准只绑定这一调用及原参数；拒绝或超时不执行该调用，Agent 继续处理原业务。硬性 BLOCK 不能人工覆盖。页面刷新会重新连接当前任务；历史上已经终止的 ASK 需重新发起运行。
复现审批可选择 `windows-approval-demo` 的干净环境；复现记忆攻防可选择 `c-memory-handoff` 的攻击环境，点击双路对决，在防护开启分支拒绝不属于摘要任务的敏感读取。大模型后续动作可能有随机性，应以每轮真实工具记录为准。
