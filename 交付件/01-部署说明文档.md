# 双镜 D²Guard 部署说明文档

> 状态：初稿。标【待定】的内容取决于快镜领域模型的最终训练结果，训练完成后填写。

## 1. 系统组成

D²Guard 以“宿主插件 + 本地防护服务”的方式接入智能体，不改动智能体本身的模型和工具。

| 组件 | 作用 | 运行位置 |
|---|---|---|
| 宿主智能体 Pi CLI | 被防护对象，真实的 LLM 工具调用循环 | 防护主机 |
| Hook 插件（`extensions/lab.ts`） | 每次工具调用执行前向内核请求裁决，执行 ALLOW / ASK / BLOCK；上报事件和子 Agent 关系 | 防护主机，随 Pi 加载 |
| API 侧网关（`src/proxy_stream.py`） | 本地流式代理：转发模型请求、对已登记凭据做出站掩码、保存请求快照；Pi 只拿到本地代理令牌，看不到上游密钥 | 防护主机 |
| MCP 中间代理 | 摄入 MCP 工具描述与返回内容，标记为不可信来源；把调用参数绑定到已批准的裁决 | 防护主机 |
| 防护内核（`src/d2v2/`） | 证据库、安全账本、策略 DSL、决策表、溯源图、慢镜队列 | 防护主机 |
| 快镜（D²Guard-Laya） | 判断外部内容是否在指使当前读者执行具体任务，并回答安全问题视图 | GPU 主机（推荐）或防护主机 CPU |
| 慢镜 | 对 ASK / BLOCK 事件做异步的反事实研判 | 任意 OpenAI 兼容接口（云端或本地 vLLM） |

三个探针（Hook、网关、MCP 代理）共用同一个内核，状态只有一份。

## 2. 硬件要求

| 角色 | 最低配置 | 推荐配置 | 说明 |
|---|---|---|---|
| 防护主机 | 4 核 CPU、8 GB 内存、10 GB 磁盘 | 8 核 CPU、16 GB 内存、SSD | 运行 Pi、Hook、网关、内核；每轮运行证据约数 MB |
| 快镜推理（GPU） | 单卡显存 ≥ 8 GB，支持 BF16 | NVIDIA A100 80GB（开发验证所用） | 实测单次推理约 1.4 GB 显存；A100 上完整裁决约 34–39 ms |
| 快镜推理（仅 CPU） | 同防护主机 | — | 可运行但延迟为秒级，只适合功能演示 【待定：领域模型在 CPU 上的实测延迟】 |
| 快镜训练 | 单卡显存 ≥ 24 GB | A100 80GB | 只在需要重训领域模型时使用 |

## 3. 软件环境

| 软件 | 版本 |
|---|---|
| 操作系统 | Windows 10/11 或 Linux（开发验证：Windows 11 防护主机 + Ubuntu GPU 主机） |
| Python | ≥ 3.11（验证过 3.12、3.13） |
| Node.js | ≥ 22.19 |
| Pi CLI | `@earendil-works/pi-coding-agent` 0.85.1（固定版本，升级前需重新验证接口） |
| Python 依赖 | `requirements-core.txt`（内核）；`requirements-laya.txt`（快镜：laya 0.4.6、torch、transformers） |
| GPU 主机 | CUDA 12.x 与对应的 PyTorch（验证过 Torch 2.10.0+cu128） |

## 4. 部署步骤

以下命令在程序源码根目录执行。

### 4.1 安装依赖

```powershell
npm install -g @earendil-works/pi-coding-agent@0.85.1
python -m pip install -r requirements-core.txt
python -m pip install -r requirements-laya.txt
```

### 4.2 配置上游模型接口

新建 `.local/provider.json`（该目录不进入版本库）：

```json
{
  "base_url": "https://<上游接口地址>/v1",
  "api_key": "<上游密钥>",
  "main_model": "<智能体使用的模型名>",
  "api_style": "responses"
}
```

`api_style` 可取 `responses` 或 `chat_completions`。密钥只由本地防护服务读取，不会出现在命令行、日志或 Pi 的配置里。

### 4.3 准备快镜模型

基础模型使用官方固定版本 `convaiinnovations/laya`（revision `7b928d828b7b0e022f929d9bd2e44165aa270148`）。下载并校验权重摘要：

```powershell
python prepare_laya.py --checkpoint english --device cuda:0   # GPU 主机
python prepare_laya.py --checkpoint english --device cpu      # 仅 CPU
```

脚本会核对官方发布的摘要，结果写入 `.local/laya.json`。权重不一致时拒绝加载，不会静默改用其他模型；配置了 CUDA 但不可用时直接报错，不会退回 CPU。

D²Guard-Laya 领域模型：【待定：领域模型权重的获取方式、`model.safetensors` 的 SHA-256、温度参数，以及 `D2_S1_CONFIG` 配置文件的写法】。

### 4.4 自检

```powershell
python -m unittest discover -s tests -v
node --test tests/boundary.test.mjs
```

### 4.5 启动一次受防护的任务

```powershell
# 无防护基线
python lab.py run --scenario readme-setup-registration --environment attack --protect off

# 开启防护
python lab.py run --scenario readme-setup-registration --environment attack --protect on
```

每次运行在 `runs/<run-id>/` 下生成完整证据，可用 `python verify_v2.py <批次文件>` 独立核验。测试样例与批量运行方法见《测试样例及测试流程说明文档》。

## 5. 部署拓扑

```text
┌──────────────── 防护主机 ────────────────┐        ┌──── GPU 主机（可选）────┐
│ Pi CLI ── Hook 插件 ──┐                  │        │ D²Guard-Laya 推理        │
│   │                   ▼                  │  本地  │ （快镜）                 │
│   └─► API 网关 ─► 防护内核（账本/策略/   │◄──────►│                          │
│        │          决策表/溯源）          │        └──────────────────────────┘
│        ▼              ▲                  │
│   上游 LLM 接口   MCP 中间代理           │──► 慢镜接口（异步，可选）
└──────────────────────────────────────────┘
```

- 裁决链路（决策表与快镜）全部在本地完成，不同步等待任何远端服务。
- 慢镜只在 ASK / BLOCK 之后异步运行，接口不可用时不影响裁决。
- 单机部署时快镜与内核同机运行；有 GPU 主机时快镜放在 GPU 主机上。

## 6. 安全与运维说明

- 上游密钥只保存在 `.local/`，由防护服务读取；Pi 只拿本地代理令牌。
- 实验中使用的凭据都是每轮随机生成的测试值，安全账本、模型输入和取证包都不含机密明文。
- 当前工具边界：文件读写限定在本轮工作区，HTTP 只开放本地测试服务，不开放任意 Shell 和互联网。这是应用层限制，不是操作系统级沙箱。【待定：是否提供容器化部署】
- 每轮运行记录源码、场景和 Pi 程序的 SHA-256，便于复现和审计。
